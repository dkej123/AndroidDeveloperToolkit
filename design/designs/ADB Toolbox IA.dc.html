02

Six decisions

The ones that shaped everything else.
The device is context, not content
Every action in the plugin targets one device, so the selector lives in a 30px pinned bar rather than a Device view. When a second device appears it becomes a popup list; with one device the bar is a read-only summary. Serial is always shown in mono because two Pixel 8 Pros are indistinguishable by name.
A rail, not tabs
Five labels would eat the full width of a 380px dock and clip. The 34px rail matches New UI tool window switching, keeps view names in tooltips, and gives each view a badge slot — the amber dot that says "this device has an override applied" is what makes overrides discoverable at all.
Presets are the interface; values are the escape hatch
Font scale and density are one-click chip rows. The custom field is collapsed behind "Custom…", and every row carries Reset. Density presets are relative percentages of the device's physical density, so 125% is meaningful across a tablet and a phone; the resolved dpi is shown in mono beside it.
Destructive actions look different before they are pressed
Clear data and Uninstall sit in a separate row from Restart and Launch, outlined in red, and are the only two actions that confirm. Both confirmations name the package and the device. Everything else is reversible and gives a toast instead of a dialog.
Logcat gets the whole viewport
It is the one view users leave open for hours, so it is the only view where the device bar collapses to a single line and filters live in a 26px toolbar. Paused autoscroll is stated twice — a toggled toolbar button and a floating "234 new lines · Jump to latest" pill — because silently frozen logs are the classic logcat bug.
Capture is deliberately quiet
Android Studio already ships screenshot and recording, so capture is two icon buttons in the Device toolbar rather than its own view. Recording promotes itself to a status-bar chip with elapsed time and Stop while it runs, and the finished file appears as a toast with Reveal.

04

Keyboard & degradation

The plugin must be usable with no device and no mouse.
Keyboard model
Tab / ⇧TabMoves between regions: device bar → rail → view → status bar. Never into individual chips.
↑ ↓ ← →Moves within a region — rail views, preset chips, app list rows, log lines.
⌘F / EscFocus the Logcat search field; Esc clears the query, then blurs.
SpaceToggles pause in Logcat, wherever focus is inside that view.
EndResumes autoscroll and jumps to the newest line.
EnterApplies a custom value; a destructive confirm still needs a second Enter on a focused Cancel-default dialog.
Degradation ladder
—adb missing: whole window becomes one empty state with a path field, not five broken views.
—No device: rail stays navigable so users can read and set up; every device-mutating control is 45% opacity with "Connect a device to use this" in the tooltip.
—Device unauthorized / offline: device bar turns amber and explains the fix; the picker keeps listing it.
—scrcpy missing: only mirroring degrades — the button stays, the failure is a toast with Set path…
—Device disconnects mid-session: overrides are remembered and offered for re-application when the same serial returns.
—Below 300px: device bar drops the serial, preset rows scroll horizontally instead of wrapping.
